## What Was Done

Project-wide rebrand replacing every in-scope reference to `OpenPaw` / `openpaw` / `Open Paw` / `OPEN PAW` / `OPENPAW` with the corresponding `TemperPaw` / `temperpaw` / `Temper Paw` / `TEMPER PAW` / `TEMPERPAW` form.

Scope followed the approved plan at `~/.claude/plans/oh-yes-skip-warp-lovely-sunset.md`:

**Included:**

## What Worked
- Five-stage case-mapped `sed` sweep (longest-case first) cleanly handled all five casing forms without cross-contamination.
- `cargo check --workspace` succeeded on the first post-rename attempt — no missed crate references.
- The rebranded CI workflow (`cargo {clippy,check,test} -p temperpaw`) compiles and tests clean.
- Frontend build succeeded without any code changes beyond the text sweep.
- All 40 `temperpaw` crate tests pass.

## What Didn't Work
- First content sweep missed hidden directories (`.github/`, `.vision/`, `.claude/agents/`, `.cargo/`, `.env.example`) because `rg` skips hidden paths by default. Caught on first post-sweep check; fixed with a second pass using `--hidden`.
- One `scripts/openpaw_proof_support.py` filename wasn't in the explicit rename list; caught by `find -iname '*openpaw*'`. Renamed. Python imports were already updated by the sed sweep.
- `cargo fmt --check` initially failed on one line in `temperpaw-cli/src/deploy.rs:292` where `temperpaw` (1 char longer than `openpaw`) pushed the line past the wrap threshold — fixed with `cargo fmt`.

## Limitations

**Not performed (out-of-band, user-driven):**
- GitHub repo rename `nerdsane/openpaw → nerdsane/temperpaw` (requires GitHub UI or `gh repo rename` with owner token). Once renamed, local remote URL needs `git remote set-url`.
- `ghcr.io/nerdsane/openpaw:edge` image path — first CI build on renamed repo will publish to the new path. Old image remains as a dangling artifact in GHCR.
- Datadog service tag — redeploying the renamed monitor/dashboard JSON will create a new `service:temperpaw`. Historical `service:openpaw` metrics stay under the old tag (no alias configured — would require manual Datadog-side work).
- Slack handle `@slack-openpaw-alerts` inside Datadog monitor JSON — intentionally left untouched. Rename only if a replacement Slack channel exists.
- Local `.env` files — not rewritten per `CLAUDE.md` "shared local state" rule. If your local `.env` has `OPENPAW_*` vars, rename them manually.

**CI baseline noise (pre-existing, not introduced by this change):**
- `paw-transport` has 5 clippy lints (`single_match`, `collapsible_if`) that fail under `-D warnings`. Present on `main` at `crates/paw-transport/src/discord/transport.rs:1036-1048` and elsewhere.
- `cargo build --workspace --target wasm32-unknown-unknown` fails because root workspace members (`temperpaw`, `paw-transport`) depend on `tokio`/`mio` which don't build for `wasm32-unknown-unknown`. Failure is identical on `main`.

## What Still Doesn't Work

Nothing blocking — the rebrand itself is complete and green on cargo check, fmt, frontend build, and `-p temperpaw` tests. Pre-existing CI weaknesses (clippy lints, WASM workspace build) are outside the scope of this change.
