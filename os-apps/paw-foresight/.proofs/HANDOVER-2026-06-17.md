## 8. The blocker — why `en-019ed392` can't reach stories

The engine moves a world forward like this: each claim settles → on a *Bridging*
claim's `RouteSettled`/`ResumeBridge`, `aggregate_costs.claim_phase` runs the
**world-aggregate** (iterates all claims; if none Bridging, dispatches
`Endpoint.ScoreComplete` per endpoint + sets the canonical path + `World.PathsScored`)
→ endpoints score → world gets a canonical path → `World.Render` → render
artifacts → `World.AnimateDwellers` → dwellers → **stories**.

The last 2 claims were wedged by bug #2, so I resolved them with operator
`Claim.MarkUnreachable`. **That bypassed the world-aggregate** (it only fires off
a Bridging claim's settle path). Now **all 21 claims are resolved but no Bridging
claim remains to re-fire the aggregate**, the 2 residual `Repaired` paths are
**409-locked** (can't Score/Prune/Fail/RequestChallenge them), and there is **no
self-heal** that runs the aggregate when "all claims resolved but canonical
unset" (gap #4). So the endpoints sit `UnderRepair` forever.

Forcing it would mean hand-dispatching `World.PathsScored` with hand-computed
endpoint weights and a hand-picked canonical path — i.e. **hand-faking engine
output**, which fails the flagship's "every artifact engine-produced, no manual
salvage" bar. **Do not do this** to call it a flagship.
