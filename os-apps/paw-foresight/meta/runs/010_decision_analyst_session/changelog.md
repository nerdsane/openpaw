# Run 010 Changelog

## Changed File
`os-apps/paw-foresight/wasm/spawn_orchestrator/src/lib.rs`

## What Changed

Added a dedicated WASM-created "decision analyst" session, following the same proven pattern
that resolved the Breadth deficit in Run 009 (cross-theme analyst). The decision analyst
addresses the Actionability deficit (-3.0 Borda in Run 009) by producing pre-computed decision
frameworks with strategic cost-benefit-risk framing that the synthesizer includes AS-IS.

### Before (Run 009)
- WASM creates: 6 probe sessions + 1 cross-theme analyst + 1 orchestrator
- Decision Points were generated by the synthesizer following template instructions
- Template instructions said to include tradeoffs but synthesizer produced formulaic output
  (engineering-weeks only, no strategic framing, no opportunity cost analysis)

### After (Run 010)
- WASM creates: 6 probe sessions + 1 cross-theme analyst + **1 decision analyst** + 1 orchestrator
- Decision analyst session:
  - Waits for all 6 probes to complete
  - Reads all observations and directions from the API
  - Identifies top 3 decision points with rich strategic framing
  - Each decision point has: who decides, timing trigger, 3 options with Cost/Risk/Opportunity cost/Strategic consequence, comparative analysis, and quantified recommendation
  - Writes output to `decision_analysis.md` workspace file
- Orchestrator waits for decision analyst (alongside cross-theme analyst)
- Orchestrator injects decision content into synthesis template via `===DECISION_CONTENT===` placeholder
- Synthesis template Step E changed from instructional to pre-computed (same pattern as Step C4)
- Synthesizer includes decision content AS-IS, no regeneration

### New WASM Constant
- `DECISION_ANALYST_PROMPT` (~3KB) — full prompt for the decision analyst session

### Modified Constants
- `ORCHESTRATOR_INSTRUCTIONS` — now waits for 3 session types (probes + cross-theme + decision), reads decision analyst output, injects into template
- `SYNTHESIS_TEMPLATE` — Step E changed from instructional to pre-computed with `===DECISION_CONTENT===` placeholder and fallback instructions

### Modified Functions
- `run()` — creates decision analyst session (Phase 2b, between cross-theme analyst and orchestrator), passes decision_sid to orchestrator prompt

## Key Design Decisions

1. **Decision analyst runs concurrently with cross-theme analyst** — both wait for probes, so they can run in parallel. No additional latency.
2. **Fallback preserved** — if decision analyst fails (same WASM error that hit cross-theme analyst in Run 009), the synthesizer falls back to generating its own decision points from the template instructions.
3. **Same structural pattern as Run 009** — WASM creates session, session produces pre-computed content, orchestrator injects into template, synthesizer includes AS-IS. This pattern has been validated: it works where prose instructions don't.
